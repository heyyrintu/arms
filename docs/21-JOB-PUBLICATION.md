## Workflow and invariants

- `/admin` links to `/admin/jobs` and `/admin/jobs/new`; saved entries reopen at `/admin/jobs/[id]`. All independently verify the live administrator session. Other staff roles currently have no job-management access.
- Save validates the known string fields, lengths, slugs, enums, date, salary disclosure and range. Undisclosed pay is discarded. No HTML is interpreted. All content is escaped when rendered.
- New drafts use a client-generated random ID retained for retries. An identical first-save retry returns the existing draft. A different payload for that creation ID conflicts; reload the saved posting. Slugs are unique. Subsequent mutations require the current revision, lock the job row, and reject stale updates rather than overwriting another edit.
- Publish requires a fresh preview of the saved revision, explicit genuine/authorized-vacancy confirmation, a 10–500-character approval reference, a confirmed ARMS-managed or client-managed payroll model, and a future closing date. The server validates these again; it records actor, approval time and approved revision. These are administrator attestations, not independent verification of external employer authorization.
- Closing dates end at 23:59:59.999 **Asia/Kolkata / UTC+05:30**, independent of the server timezone. The editor currently requires a later calendar date. Exact same-day closures can use Close job.
- Editing published content immediately saves it as a private draft and clears approval. Publication needs another preview and approval. The slug cannot change after its first publication.
- Close and archive remove the job from public reads. Archive is reversible. Restore returns closed/archived jobs to draft, never straight to publication. There is no permanent-delete endpoint.
- An authenticated administrator has a shared database limit of 30 mutations per minute. POST uses exact configured Origin, rejects cross-site requests, bounds JSON to 32 KiB, and returns only committed results. Timeouts are uncertain outcomes: keep the page open and retry the same creation ID or reopen the saved record. Errors never claim a save/publish succeeded.

## Public behavior and scope

Home, job list, job detail and `/api/jobs` read the approved projection on each server request with no shared data cache. Closed, draft, archived and expired detail URLs return 404; a database outage produces an explicit unavailable state. Public API responses are no-store. The list/search currently covers the latest 200 jobs (the UI discloses that cap when reached); administrator lists show the latest 100, and each saved activity view shows the latest 30 events at page-load time. Larger catalogues need server-side filtering/pagination before expanding those bounds.

Configured live queries never mix in development sample jobs. Unconfigured development may still show the existing labelled, inert samples; production always excludes them. The preview banner does not assert there are no live jobs after publication. All pages remain no-index until the separate launch flag is approved. Public application, talent and employer POST APIs remain 503 and public forms remain disabled, including on genuine job details. Private CV processing and privacy/retention enforcement are not enabled by job publication.
